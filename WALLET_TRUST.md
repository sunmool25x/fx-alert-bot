## Confirmed source of the mismatch

The owner reported OKX's “Domain mismatch” warning after scanning the external Sepolia Etherscan Write Contract QR. This QR was generated by Etherscan, not by FX Alert Bot, its Telegram Mini App, localhost or the development tunnel.

The public [Etherscan Reown helper](https://sepolia.etherscan.io/assets/js/custom/reown-helper.js?v=26.9.2.5), in `initReownModal`, passes the following identity to AppKit 1.6.9. The function is called from the Sepolia Write Contract iframe's `walletConnect_reown` route. The address page's `addresspage4.js` loads that iframe from the same Sepolia origin.

| Identity surface | Evidence |
|---|---|
| Actual QR page origin | `https://sepolia.etherscan.io` |
| Write Contract iframe origin | `https://sepolia.etherscan.io` |
| Published metadata name | `Etherscan` |
| Published metadata URL | `https://etherscan.io/` |
| Published icon | `https://etherscan.io/favicon.ico` |
| Published redirect | None configured in `initReownModal` |
| Requested network | The Write Contract route supplies Sepolia, chain 11155111 |
| OKX's actual displayed identity / Verify result | Not captured; the owner did not recall it and the browser tab was no longer available |
| Historical pairing/session identifier | Unavailable; no browser session storage was read, cleared or reconstructed |

**The concrete defect is the missing `sepolia` subdomain in the third party's advertised metadata URL.** [Reown's provider documentation](https://docs.reown.com/advanced/providers/ethereum) requires that metadata URL match the actual domain and subdomain. This confirms a source-level cause consistent with the reported warning; it is not a capture of OKX's internal Verify verdict. A changed tunnel or stale bot session is not the source of this particular QR. No stale third-party session was invalidated, and no third-party metadata was overridden.

## Mitigation and application guards

We cannot patch Etherscan's deployment. Do not reuse its affected WalletConnect QR for approvals, impersonate Etherscan, suppress its warning, or describe the warning as fixed. Keep the external flow on hold. Etherscan's [documented direct wallet connection](https://info.etherscan.com/connecting-your-wallet-on-etherscan/) is an alternative to assess using OKX's in-app browser/injected provider: it must retain the actual Sepolia Etherscan identity and be independently checked on the owner's device before a claim. Do not describe this alternative as already verified or silently migrate the bot connector to it.

FX Alert Bot's connection identity remains **FX Alert Bot** at its own current HTTPS origin:

- The authenticated server origin must exactly match the browser origin before wallet selection or SDK initialization. Subdomains are compared exactly; insecure, local, credentialed and non-origin URLs are rejected with `WALLET_ORIGIN_MISMATCH`.
- Reown metadata and the icon are generated from that matched origin. An approved session's own metadata is checked again; a previous tunnel domain, different name/icon, or unexpected redirect is rejected and that attempt is retired.
- OKX Connect 1.9.1 still derives `origin` and `url` (hostname) from its same-origin isolated frame. Only the truthful name/icon are supplied; no third-party identity override is added. Its existing memory-only session isolation, exact topic binding and Sepolia-only request allowlist remain intact.
- Desktop QR connections have no phone callback. Mobile callbacks remain the existing native Telegram routes: `tg://resolve` for OKX Connect, `tg://resolve?domain=world_fx_alert_bot` for Reown. These return routes are not advertised dApp origins. Arbitrary HTTPS callback hosts are not introduced.
- The Korean/English connection panel shows TESTNET, selected wallet, Sepolia, connection/ownership purpose, the actual expected domain and “Connecting does not authorize a swap.” Origin failures stop before opening/signing instead of exposing SDK payloads.

Quick Tunnel names remain development-only. A new host requires a fresh page and fresh connector attempt; old metadata must never be advertised under a new origin. A stable HTTPS hostname and any required provider domain configuration are beta prerequisites, followed by an actual warning-free wallet check. Neither a stable hostname nor these local guards guarantee that OKX's independent trust service will approve a domain. No production deployment was performed.
