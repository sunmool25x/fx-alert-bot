## Evidence and selected path

- **DOCUMENTED / LIVE READ-ONLY VERIFIED:** [testnet API](https://docs.testnet.sera.cx/api-reference/), [authentication](https://docs.testnet.sera.cx/api-reference/authentication/), [swaps](https://docs.testnet.sera.cx/api-reference/endpoints/swaps/). API `https://api.testnet.sera.cx/api/v1`; chain 11155111. GET /config supplies Sera signing domain, SOR spender and Vault roles. Live domain is Sera/version 1, verifying Sera, not SOR. Recheck roles and on-chain domain at use time.
- **DOCUMENTED / LIVE READ-ONLY VERIFIED:** POST /swap/quote supplies a quote UUID, separate composite uint256 Intent.uuid, ~30-second quote expiry, and separate requested Intent deadline. Intent fields in order: taker/address, inputToken/address, outputToken/address, maxInputAmount/uint256, minOutputAmount/uint256, recipient/address, initialDepositAmount/uint256, uuid/uint256, deadline/uint48. Sign unchanged. The cache UUID is independent of the UUID bits inside the composite Intent ID, as live reads established. Bind both exactly in the stored version digest; never derive one from the other.
- **DOCUMENTED / LIVE READ-ONLY VERIFIED:** wallet-funded receive_less USDC → XSGD, six decimals, 100 USDC returned positive output. Initial deposit = maximum input = requested raw input. Output is a minimum, not an expected fill. Live permit domain was CIRCLE/version 1, unlike the illustrative USD Coin/version 2 example: never hardcode the example. Permit required even with existing allowance. ERC-2612 fields owner, spender, value, nonce, deadline; spender is live SOR. Verify token DOMAIN_SEPARATOR and nonces via RPC. Reject other funding paths.
- **DOCUMENTED:** POST /swap body `{uuid,signature,permit_signature,permit_deadline}`. Accepted success/trade_id/pending is not settlement. Never retry this POST automatically. The quickstart omits permit fields and suggests retrying; the dedicated endpoint reference and live permit response take precedence. User policy prohibits silent re-quotation/re-submission.
- **DOCUMENTED:** [SOR contract](https://docs.testnet.sera.cx/contracts/sor/) and [official source](https://github.com/sera-cx/orderbook-contract-v2/blob/audit/src/SeraSOR.sol) define IntentMatched(bytes32 indexed intentHash,address indexed taker,uint256 legCount). The emitted hash is the **struct hash**, not the full EIP-712 digest. It binds tokens, recipient, amounts, UUID and deadline. The contract enforces the signed envelope and final recipient before emitting the event. Independent ABI definitions only; no contract implementation copied.
- **Selected authoritative settlement read:** public Sepolia SOR event logs plus canonical successful receipt and finalized-block evidence, bound to that exact struct hash and taker. This is a Sera contract read, not the authenticated REST account history. Start scanning from a persisted pre-submission block. Batched/relayed transactions are supported; sender need not be the user. No event is UNKNOWN/PENDING, never success or permission to retry. Finalized policy is stricter than a small fixed confirmation count; disappearance is flagged on recheck. RPC must support finalized blocks and bounded eth_getLogs. This path must pass live owner acceptance before an end-to-end claim.
- **DOCUMENTED:** [orders](https://docs.testnet.sera.cx/api-reference/endpoints/orders/) provides authenticated GET /orders/{trade_id}, GET /orders and /fills. [MCP settlement tool](https://github.com/sera-cx/sera-mcp/blob/main/src/tools/settlement.ts) is a pass-through without normalized settlement guarantees. These require per-wallet keys; the selected public contract path avoids credentials, encryption keys and extra financial signatures. No operator key is used.
- **DOCUMENTED:** [quickstart](https://docs.testnet.sera.cx/quickstart/) identifies the Sera Sepolia faucet contract 0x4FAc3BB8B77547E2Da7ed903baDBeD2f46cBe65a and [testnet app](https://testnet.sera.cx/). Faucet eligibility, exact stablecoin distribution and owner acquisition remain **UNRESOLVED / live acceptance pending**. No faucet endpoint or claim transaction is invented. Only already-funded registry USDC wallets can proceed. Do not buy assets.
- **DOCUMENTED:** [Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app): backend HMAC initData, auth_date check; never trust initDataUnsafe. Inline web_app private-chat launch only. No external browser bearer-link handoff.
- **DOCUMENTED:** [Reown Ethereum Provider](https://docs.reown.com/advanced/providers/ethereum): WalletConnect EIP-1193 connector, Sepolia only, user-selected wallet via QR/mobile connector; no injected-wallet assumption. [SIWE](https://eips.ethereum.org/EIPS/eip-4361) ownership proof uses a server nonce, origin, chain, purpose, expiry. viem verifies EOA signatures. Smart wallets and delegated-code accounts are rejected in this MVP.

Developer docs https://docs.dev.sera.cx/, agents https://agents.sera.cx/docs/ and official https://github.com/sera-cx were inspected. No second MCP runtime or community code is introduced. Existing MIT attribution remains intact. Source facts are independently implemented.

## Scope and live acceptance

One connector; same-wallet recipient; wallet-funded ERC-2612 USDC → XSGD only, maximum 100 test USDC (operator may lower, never raise above this ceiling). All other read-only pairs remain available. No limit orders, approvals, deposits, vault funding, transfers, NLU or analytics.

No **LIVE USER-VERIFIED** evidence exists. Telegram token, public HTTPS origin, Reown project configuration, owner wallet/funding, and RPC capabilities must be supplied/tested by the owner. Missing setup must not break market/alert/scanner features. Automated implementation and live read-only checks will be recorded separately in STATUS.md.
